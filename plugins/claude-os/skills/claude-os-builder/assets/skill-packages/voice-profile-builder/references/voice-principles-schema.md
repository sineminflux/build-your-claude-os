# voice-principles.md Schema

The structure for the principles file. This is the one an AI loads on every draft, so it must be lean and dense. Target roughly 120 to 200 lines. Sections in this order. Content adapts to the person. The order does not.

Build in this priority order, and if you must trim to fit, trim from the bottom and never cut the anchor examples.

---

## Header

One line naming who this writes as, and a line telling the AI to prefer this voice over its defaults. Then what it was built from (how many pieces, which channels), so a later reader knows the source base. Add a precedence line: when these rules conflict with a specific instruction given in the moment, follow the instruction.

## Sentence style (measured)

The numbers from Layer 1 as instructions: median and mean length, the variance rule, the real long tail, contraction density by register, one-sentence-paragraph rate. Numbers, not adjectives.

## Punctuation and emphasis

The fingerprint from Layer 2, including the bans.

## Structure and signature moves

Openers used and openers never used, the spine habit, the metaphor well, development habits, and how pieces close. Each with a real example where it helps.

## A few anchor examples

Three or four of the shortest, highest-signal verbatim passages, each labeled with the move it shows. These live here so a single load of this file is never without examples. The full annotated set lives in the companion voice-examples.md. Point to it here.

## Off-brand vs on-brand pairs

Two or three calibration pairs from Layer 7. Each "on-brand" line should be a real sentence the person wrote.

## Register table

The per-platform table from Layer 6. Mark inferred rows honestly.

## Words and phrases to avoid

The tailored never-list from Layer 4. Their real risks and dealbreaker, not a generic cliche dump.

## Words and phrases I use

The signature language from Layer 5, with the "recognize, don't manufacture" caution.

## Self-check before publishing

A short checklist framed as questions the writer (or AI) runs before shipping. Make the items specific to this voice, not generic. A generic checklist item that applies to any writer adds nothing.

## Keeping this file accurate

Three things: a learn-from-my-edits line (treat any correction to a draft as a correction to this file), a refresh cadence, and a note on which gaps to close next (usually the registers with the thinnest samples). End with a dated changelog.

---

## Design rules for this file

- Patterns over descriptions. "Sentences alternate short punches and medium explanations" beats "dynamic rhythm."
- Examples over rules where you can afford the lines.
- Lean wins. Cut anything that doesn't change what a draft would look like.
- Every claim is anchored to a real line. No aspirational voice, only observed voice.
- No vibe layer. This file is measured mechanics, observable moves, and real examples. If a line could describe any writer, it doesn't belong.
